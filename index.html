Client Intake & Project Scoping Pipeline

Problem

Consulting firms waste hours manually processing client inquiry forms — reading emails, extracting requirements, classifying needs, and producing project scopes. Every client uses different language; no two intake forms look alike. This mismatch causes inconsistent scoping, missed requirements, and slow turnaround.

Objective

Build an automated pipeline that ingests client data in any format (JSON, CSV), validates it, classifies the need using a rule engine, generates a structured project scope document, and outputs a formatted report — all in a single, auditable pass. No APIs, no external services — pure Python stdlib.

Approach

We chose a modular 5-stage pipeline architecture (Ingest → Validate → Classify → Scope → Output) over an LLM-based approach because the classification rules are deterministic and auditable — when a client says "CRM integration," we need to map that to a known category with confidence scoring, not generate a probabilistic guess. A keyword-based rule engine with 10 service categories gives us perfect reproducibility.

Implementation

Each pipeline stage is an independent function in client_intake_pipeline.py. Stage 1 auto-detects file format (JSON/CSV) and walks directories recursively. Stage 2 checks 5 required fields per record with error logging. Stage 3 matches against configurable CLASSIFICATION_RULES — a dict of keywords mapped to categories, sub-categories, and complexity weights. Stage 4 uses Jinja-style string templates (stdlib string.Template) for scope generation. Stage 5 writes individual Markdown reports plus a summary index.

📁 Evidence: Sample intake data at intake_data/ — see sample_client.json and generated reports in output/.

Result / Output

The pipeline processes 7 sample client records (3 JSON + 4 CSV) in under 0.5 seconds. Each record generates a comprehensive scope document with: objective, deliverables, tech stack, timeline, budget range, risk factors, and next steps. The summary index links all reports for at-a-glance portfolio review.

🖼️ Screenshot: To be captured — sample output Markdown renders cleanly in any viewer.

Technical Details

  • Stack: Python 3.10+ (stdlib only — zero dependencies)
  • Architecture: 5-stage pipeline with clean input → process → output separation
  • Classification: Keyword-based rule engine with confidence scoring (0–1) and complexity estimation (Low/Medium/High)
  • Template Engine: string.Template — 8 service category templates + general fallback
  • Testing: pytest suite covering validation, classification, and output stages

Limitations & Future Work

  • Current keyword rules are static — future versions should support YAML-configured rule sets without code changes
  • No LLM fallback for ambiguous classifications (intentional — keeps the pipeline deterministic)
  • Streamlit UI exists (streamlit_ui.py) but needs deeper integration with the pipeline output
  • Could support PDF intake documents via OCR pre-processing stage

Philippine Coffee Shop Market Intelligence Dashboard

Problem

Philippine business stakeholders lack accessible, consolidated market intelligence on the local coffee shop industry. Data is scattered across Euromonitor reports, USDA briefs, news articles, and company filings — making it nearly impossible to get a coherent picture of market size, competitive dynamics, pricing, and geographic distribution without a dedicated research team.

Objective

Build an interactive, Streamlit-hosted dashboard that consolidates Philippine coffee shop market data into a single view — spanning market overview, competitor analysis, geographic distribution, pricing analysis, and key business insights. Target: an entrepreneur or investor who should understand the market in 10 minutes, not 10 hours.

Approach

We chose a dashboard over a static report because market intelligence is inherently exploratory — a decision-maker needs to filter by region, drill into competitor detail, and toggle between views. Streamlit gave us the fastest path from pandas dataframes to interactive Plotly charts without a separate frontend framework. The data pipeline (clean → transform → analyze → export) is separated from the dashboard layer so the analysis is independently testable and reusable.

Implementation

pipeline.py handles all data processing: ingests raw CSVs, computes derived metrics (YoY growth, CAGR, import dependency ratio), and exports clean datasets plus 13 Plotly HTML charts. dashboard.py presents 5 tabbed pages in Streamlit — each with KPI cards, interactive charts, and toggleable views. The viz/ directory contains standalone HTML charts for offline sharing.

📁 Evidence: See business_insights.md for 13 data-driven findings, and viz/ for standalone HTML charts.

Result / Output

The dashboard reveals a $1.82B (2025) market projected at $2.30B by 2028 (7.3% CAGR). Key insight: Zus Coffee's 100% YoY store growth signals that the value segment is the battleground. Starbucks leads premium with 520 stores but commands 2.6× the average price of value players. 80% of Filipino adults drink 2.5 cups/day — massive total addressable market with low specialty penetration (14%) indicating headroom.

🖼️ Screenshots: To be captured — dashboard renders 13 interactive Plotly charts across 5 pages.

Technical Details

  • Stack: Python, pandas, Plotly, Streamlit
  • Data Sources: Euromonitor, USDA, Statista, company filings, store locator websites (2024–2026)
  • Analytics: Market sizing (top-down + bottom-up), competitive positioning maps, price ladders, geographic density heatmaps
  • Visualization: 13 interactive Plotly charts, KPI cards, tabbed dashboard layout
  • Deployment: Streamlit Cloud — URL to be added after deployment

Limitations & Future Work

  • Data is manually collected — an automated news/data ingestion pipeline would keep insights fresh
  • No real-time pricing data; menu prices are point-in-time snapshots
  • Geographic data is aggregated at regional level — store-level coordinates would enable richer spatial analysis
  • Could add sentiment analysis on social media mentions for brand perception tracking

RFP / RFQ Analyzer

Problem

Procurement teams spend hours reading PDF-based RFPs and RFQs — extracting deadlines, eligibility criteria, deliverables, evaluation criteria, and risks. RFP documents are dense, inconsistent in format, and easy to miss details in. A missed deadline or overlooked eligibility requirement can disqualify a bid worth millions.

Objective

Build an AI-powered system that extracts structured information from procurement PDFs — deadlines, eligibility, deliverables, evaluation criteria, budget, risks — and presents them in a clean, auditable interface. The output must be validated against a defined schema so no critical field is silently dropped.

Approach

We chose an LLM-in-the-loop architecture over pure regex because procurement documents vary wildly in structure — a regex approach would require perpetual maintenance. Three independently testable layers (PDF parsing → LLM extraction → Pydantic validation) let us swap any component without touching the others. The Pydantic validation layer ensures the LLM's output is schema-compliant; fields missing from the document are gracefully omitted rather than hallucinated.

Implementation

PyMuPDF extracts raw text from PDF uploads. The analyzer sends extracted text to an OpenAI-compatible LLM with a structured output prompt. The response is validated against RFPParseResult (Pydantic model) — catching malformed fields before they reach the UI. The Streamlit frontend presents results in collapsible cards: summary, dates, deliverables, eligibility, evaluation criteria, budget, risks. A bundled 5-page sample RFP (sample_docs/) lets users test without uploading their own documents.

📁 Evidence: See sample RFP PDF and test suite in the repository.

Result / Output

The system extracts 7 structured fields from procurement PDFs with schema validation — eliminating manual extraction. The collapsible card UI lets procurement teams scan extracted data at a glance, expand for detail, and inspect raw JSON for auditing. The test suite validates both happy-path extraction and edge cases (missing fields, malformed documents).

🖼️ Screenshot: To be captured — Streamlit UI with collapsible extraction cards.

Technical Details

  • Stack: Python, PyMuPDF (fitz), OpenAI API, Pydantic, Streamlit
  • Architecture: PDF Parser → LLM Analyzer → Pydantic Validation → Streamlit UI
  • Schema: Pydantic model with 7 structured fields + graceful omission for missing data
  • Testing: pytest with sample RFP PDF, edge case test fixtures
  • Chunking: Long-document support for documents exceeding LLM context windows

Limitations & Future Work

  • LLM extraction cost — per-document API calls add up for high-volume procurement teams
  • No image/chart extraction from PDFs — tables in scanned documents are not parsed
  • Multi-document comparison (e.g., compare 3 vendors against one RFP) is not yet supported
  • API key must be provided by the user — future version could offer a server-side key pool

Customer Feedback Intelligence System

Problem

Philippine businesses collect customer reviews across multiple channels (Shopee, Lazada, Google Maps, Facebook) but lack the tools to systematically extract signal from noise. Raw review text hides actionable patterns — which product features drive negative sentiment, which customer segments are most dissatisfied, and whether issues are trending up or down.

Objective

Build an NLP pipeline + interactive dashboard that ingests customer review data, runs sentiment analysis, discovers topics via unsupervised learning, detects temporal trends, and generates prioritized action recommendations. All analysis must be interpretable by non-technical business stakeholders.

Approach

We chose VADER for sentiment analysis because it works out of the box on social-media-style text (emoticons, intensifiers, negations) with zero training data — critical for a Philippine market where no labeled sentiment dataset exists. For topic extraction, TF-IDF + NMF gives interpretable, additive topics without needing a GPU or labeled data. The rule-based recommendation engine converts statistical findings into actionable business language without requiring an LLM for every analysis run.

Implementation

nlp_pipeline.py contains the full pipeline: VADER compound scores map to positive/neutral/negative, TF-IDF vectorization (max_df=0.8, min_df=2) feeds NMF decomposition into 5 topics with top-8 keywords each, and reviews are assigned their dominant topic. Monthly temporal aggregation surfaces sentiment and rating trends. The recommendation engine applies hand-crafted rules: product quality issues (low-rated keywords), category hotspots (most negative category), shipping complaints, pricing perception, and emerging complaint clusters. dashboard.py renders all outputs in a four-tab Streamlit app.

📁 Evidence: See reviews.csv (100 sample reviews, Jan–Sep 2025) and the full NLP pipeline.

Result / Output

The dashboard reveals sentiment distribution (pie + KPI cards), 5 interpretable topics with keyword summaries, monthly sentiment/rating trends (dual-axis chart), and 5 categories of actionable recommendations. A product manager can open the dashboard and know within 30 seconds which issues need immediate attention.

🖼️ Screenshots: To be captured — dashboard showing sentiment overview, topic clusters, and trend charts.

Technical Details

  • Stack: Python, VADER, scikit-learn (TF-IDF + NMF), pandas, Plotly, Streamlit
  • Sentiment: VADER compound score → 3-class (positive/neutral/negative)
  • Topics: TF-IDF vectorization → NMF decomposition (5 topics, 8 keywords each)
  • Trends: Monthly temporal aggregation with dual-axis (rating + review volume)
  • Recommendations: 5 rule-based categories — product quality, sentiment hotspots, shipping, pricing, emerging complaints

Limitations & Future Work

  • VADER is English-only — Taglish (Tagalog + English) reviews need a custom or multilingual sentiment model
  • Topic count (k=5) is fixed — dynamic elbow-method selection would improve accuracy as datasets grow
  • No automatic data ingestion — CSV upload boundaries limit real-time monitoring
  • Could add LLM-powered summary generation for each topic cluster

Daily Competitive Intelligence Brief

Problem

Philippine businesses operate in a fast-moving competitive landscape where tracking competitors manually — checking news, monitoring hiring, comparing features, tracking pricing changes — is impractical. Most SME decision-makers rely on anecdotal intel, missing critical shifts until it's too late.

Objective

Build an automated agentic workflow that collects competitor data from multiple simulated sources, runs multi-dimensional analysis (features, sentiment, hiring, pricing), and produces a structured daily intelligence brief — all in a single pipeline execution. The output must be decision-ready, not a data dump.

Approach

We chose a modular collect → analyze → synthesize → report architecture because real competitive intelligence pipelines evolve constantly — new data sources get added, analysis dimensions change, report formats shift. Each stage is an independent module (collector.py, analyzer.py, reporter.py) orchestrated by pipeline.py. This lets us swap in real APIs (NewsAPI, LinkedIn, Crunchbase) for simulated data without refactoring analysis or reporting logic.

Implementation

collector.py gathers competitor profiles, news summaries, job postings, feature matrices, and pricing tiers from simulated public sources (3 AI-analytics competitors + our product profile, each with 13 features and 3–4 pricing tiers). analyzer.py runs 5 analysis engines: feature gap analysis, sentiment scoring, hiring signals, pricing comparison, and a weighted composite competitive score (5 factors: feature breadth 30%, quality 25%, sentiment 15%, pricing 15%, scale 15%). reporter.py assembles findings into a structured daily brief with executive summary, scorecards, positioning chart, and prioritized recommendations.

📁 Evidence: See generated today's daily brief and sample brief in the repository.

Result / Output

The pipeline generates a complete daily brief in under a second (stdlib only, zero external deps). The brief includes: executive summary, per-competitor scorecards, composite competitive positioning, feature gap matrix, and 3–5 prioritized action recommendations. A Streamlit UI (streamlit_ui.py) provides an interactive overview for stakeholders who prefer a visual interface.

🖼️ Screenshots: To be captured — Markdown brief renders cleanly; Streamlit UI view planned.

Technical Details

  • Stack: Python 3.13+ (stdlib only — zero external dependencies)
  • Architecture: Collect → Analyze → Synthesize → Report; modular, independently testable stages
  • Analysis: 5 engines — feature gap, sentiment, hiring signals, pricing, composite scoring
  • Scoring: Weighted 5-factor competitive score with configurable weights
  • Output: Markdown brief (stdout + file), JSON mode for API consumption, Streamlit UI

Limitations & Future Work

  • Data sources are simulated — real NewsAPI, LinkedIn, and Crunchbase integration is the next step
  • No persistent storage — each run starts fresh (intentional for a daily batch, but historical tracking needs a database)
  • Sentiment analysis is basic keyword-based — an LLM-based sentiment analyzer would improve nuance
  • Alert system (Slack/email notifications when a competitor passes a threshold) is not yet implemented

Research-to-Decision: Philippine Specialty Coffee Market Entry

Problem

A mid-cap F&B group considering Philippine market entry needs a defensible, data-driven answer to "Should we enter the Philippine specialty coffee market?" Traditional consulting engagements take 8–12 weeks and cost PHP 1–3M. Smaller firms and startups lack the budget for bespoke market research but still need rigorous analysis before committing PHP 80–120M in entry investment.

Objective

Produce a structured research-to-decision pipeline that answers a strategic business question through multi-dimensional analysis: market sizing, competitive analysis, pricing, customer segments, risk assessment, and investment recommendation — all documented with transparent methodology, assumptions, and evidence.

Approach

We used a structured PICO/PESTEL → Data Collection → Market Sizing → Competitor Analysis → Pricing → Customer Segmentation → Risk Assessment → MCDA framework grounded in economics and strategic management theory. Multi-Criteria Decision Analysis (MCDA) with weighted scoring gives us a composite Go/No-go threshold (70/100) that is transparent, defensible, and adjustable. We preferred this over a simple pros-cons list because capital allocation decisions need weighted trade-offs.

Implementation

The market-entry-analysis.ipynb Jupyter notebook walks through all 8 stages interactively. Data was collected from Philippine government sources (PSA, BSP), industry reports (Euromonitor, Kantar), and academic literature. Market sizing uses both top-down (total coffee market → specialty subsegment → addressable market) and bottom-up (store-unit economics × location capacity) approaches. Competitor analysis uses Porter's Five Forces + Strategic Group Mapping. The MCDA framework scores 7 dimensions with transparent weights, producing a 74.7/100 composite — a Conditional GO.

📁 Evidence: See the full decision report, interactive notebook, and datasets. Visual evidence: competitor map, market sizing, MCDA scoring, risk heatmap.

Result / Output

Composite score: 74.7/100 — Conditional GO. Recommendation: Enter via phased strategy — launch 3 pilot stores in Metro Manila CBDs (BGC, Makati, Ortigas), validate unit economics over 12 months, then scale regionally with a capital-light franchise model. The output includes 7 visualization assets (competitor map, market sizing, customer segments, macro context, MCDA scoring, pricing benchmark, risk heatmap, unit economics).

🖼️ Visual Assets (live): Competitor strategic group map, Market sizing chart, Risk heatmap (all committed to repo).

Technical Details

  • Stack: Python, Jupyter, pandas, matplotlib, seaborn
  • Framework: PICO/PESTEL → MCDA with 7 weighted dimensions
  • Analysis: Top-down + bottom-up market sizing, Porter's Five Forces, strategic group mapping, scenario analysis
  • Risk: Regulatory, supply chain, competitive response, macroeconomic — each with mitigation strategies
  • Output: 347-line decision report, interactive notebook, 7 visualization PNGs, 3 CSV datasets

Limitations & Future Work

  • Philippine-specific consumer survey data would strengthen customer segment assumptions
  • Real estate cost data by specific CBD location would improve bottom-up economics
  • Exchange rate sensitivity analysis (PHP/USD) is not modeled
  • Would benefit from a Streamlit frontend that lets users adjust MCDA weights and see real-time score changes
